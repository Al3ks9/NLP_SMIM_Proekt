# Thesis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the remaining evaluation code (word-substitution scoring, Gemma test eval, human-evaluation page and aggregation, data-limit analysis, half-data SFT switch, example picker) and the thesis skeleton, then drive the runs and chapter writing in the spec's order.

**Architecture:** Every new module is a small CLI under the pipeline that owns it, reading the existing generation CSVs (`source_poem_id, target_author, generated_poem, …`) so all systems are scored by the unchanged `compare_generations`. The rating page is one self-contained HTML file rendered by Python from a template plus an inlined JS file; ratings come back as JSON files in `data/human_eval/`.

**Tech Stack:** Python 3.11 (`uv`), pytest, existing `common.*` / `students.shared.*` modules, vanilla HTML/JS (no build step; `node` only for tests), matplotlib via `uv run --with matplotlib` (not a project dependency), XeLaTeX.

**Spec:** `docs/superpowers/specs/2026-11-08-thesis-plan-design.md`

## Global Constraints

- Thesis entirely in Macedonian, abstract included; written in English first, translated by the author chapter by chapter. 20–30 pages body.
- Two author counts: corpus and splits 1,239 poems / 38 authors; everything stylometric 24 authors with ≥ 5 poems (`MIN_POEMS = 5`, 1,207 poems in `pos_tagged.csv`).
- Dependency rule (enforced by `tests/test_layout.py`): `common` imports no pipeline; `word_substitution < llm_infill < gemma_teacher < students`; `students/shared` imports neither `qwen` nor `gemma`.
- Run modules with `uv run python -m <package>.<module>`; resolve `data/`/`models/` through `common.paths.ROOT`.
- Teacher test outputs come from the API only (`data/synthetic/teacher_test.csv`); never mix vLLM rows in.
- Human evaluation: 20 test pairs (2 per target author) × 6 systems (teacher, Qwen SFT, Qwen GRPO-v2, Gemma SFT, Gemma GRPO, real-poem control) = 120 items; six 1–5 scales; Macedonian labels; panel of 3 train-split poems per target (prefer 8–30 lines); control = target's train poem with highest line-F1 to the source, never a panel poem; control is shown blind with all six scales and its content score is excluded in analysis.
- Gemma GRPO starts only once merged ≈ adapter-on on the real SFT adapter.
- No commits by Claude unless the author asks; no `Co-Authored-By` / "Generated with" lines ever.

## Review Focus

- A rater's browser loses `localStorage` (private window, cleared data) mid-run → page still works, warns once that progress won't persist, Export still has everything rated this session. (Task 4 test: storage accessor wrapped; manual check in Step 7.)
- Two raters with the same name → same order and same storage key; the export includes the rater name and a start timestamp, and `summarize` treats files as distinct raters by file name. (Task 5 test.)
- A system CSV missing one of the chosen pairs → `select_pairs` only picks pairs present in **every** system CSV and fails loudly if an author has < 2 such pairs. (Task 3 test.)
- A poem containing `<`, `&` or `</script>` → rendered as text, page not broken. (Task 4 test.)
- `ratings_*.json` from an older page version (different item set) → `summarize` rejects it by `page_version` rather than silently joining wrong items. (Task 5 test.)
